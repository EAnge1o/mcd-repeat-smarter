## 2. 会话脉络

### 阶段 0：接任务与方向确认

1. 用户给出官方仓库 `M-China/mcd-developer-innovation-challenge`，要求用 WorkBuddy 开发参赛项目。
2. 我先做了**赛道调研**（拉 `RANKING.md` + 检索同类仓库），最初建议做"团餐拼单/AA 分账"，理由是看起来是空白。
3. 检索后发现这个判断是错的——`mcd-social-suite`、`mcd-meal-brain`、`mcd-group-order`、`mthli/mcd-order`、`mcd-catering-butler` 等已经占了这块。**我主动告知用户判断有误并重新筛选方向。**
4. 最终选定「麦麦老样子」：不做泛化推荐，做"重复点单 + 增量修改 + 真实核价 + 确认下单"。

### 阶段 1：先验证真实能力，再设计功能

在写任何业务代码前，先用一个零依赖 Python 探测器（`probe/mcd_probe.py`，仅标准库 urllib）打通 MCP：

- 确认传输方式、协议版本、会话头、认证头；
- 导出**全部 35 个真实 Tool**（比公开文档多，含文档未收录的 `query-survey-coupon`、`query-promotions`）；
- 用真实账号拉历史订单、真实菜单、真实核价、真实券。

这一步产出了几个直接影响实现的结论：

| 发现 | 对实现的影响 |
| --- | --- |
| `calculate-price` 返回「分」，`query-meals` 的 `currentPrice` 是「元」字符串 | 领域层统一存「分」整数 |
| 用户历史 10 单里最爱的 `随心配1+1`（9900010829）**已下架** | 必须做"商品身份重匹配 + 显式告知"，这是本项目最核心的差异化 |
| `精选超值随心配`(9900013291) 能完整复现用户习惯（鸡排 + 香芋派） | 候选生成要按"轮次结构"而不是按商品名 |
| 历史订单不返回轮次、不返回图片 | 子项匹配先全套餐搜索再反推轮次 |
| 含 `unselectedKey` 的特调组必须整组传 | 漏传会静默按全配计价 |

### 阶段 2~3：搭架构 + 打通核心闭环

按模块拆分实现：意图解析（规则引擎）→ 原方案匹配 → 增量修改解析 → 候选生成 → 官方核价 → 预算校验 → 确认状态管理 → 持久化。

**开发中真实修掉的 bug：**

1. `add` 分支排在 `locateTarget` 之后，导致"加一份麦乐鸡"被吞 → 调整分支顺序；
2. 备选方案生成不出来：在"已被修改的 items"上定位目标 → 改在原始方案 `baseItems` 上定位；
3. 子项匹配只在推断轮次内搜索，导致换了轮次的同名商品被误判 → 改为全套餐搜索；
4. `随心配1+1` 匹配不到 `人气经典随心配`（相似度 0.43）→ 修正包含关系的相似度算法，阈值 0.7 → 0.62；
5. 测试断言本身写错（用了能精确匹配的商品去测别名分支）→ 换商品修正。

### 阶段 4：视觉方向的三次推倒重来

界面方向前后被推翻三次，每次都是**换设计系统，不是换配色**：

| 版本 | 方向 | 结果 |
| --- | --- | --- |
| v1 | 柜台纸 / 收据小票隐喻 | 否掉——像印刷品试验，不像是能点单的界面 |
| v2 | 日系美食手账（贴纸、手写体、胶带） | 否掉——装饰压过信息，价格看不清 |
| v3 | 日系独立杂志（大留白、极细字重、竖排小标） | 否掉——参考感太强，产品感不足 |
| v4 | 克制的商业点单界面（暖白底 + 纯白卡片 + 1px 细线 + 品牌红只用于主路径） | 通过，成为本阶段的定版 |

v4 的关键界面：首屏"今天，还是老样子？"（标题 / 输入 / 主图三区网格）、改了什么（前后两栏对照）、候选方案（带 traceId 与官方核价来源）、确认弹层（勾选才可下单）。结果页刻意收窄到 900px 居中——它是决策页，不是浏览页。

用 Puppeteer 驱动本机浏览器自动化走通主流程并截图，**浏览器控制台零报错**；随后按截图逐条修：全角逗号在 56px 下的巨大空隙、中文标题被 flex 压成「改了什 / 么」、顶栏门店名过长导致 320–430px 横向溢出、0 元订单金额抢注意力、确认页重复出现两次「应付」、空状态卡片只占半行。

### 阶段 5：横向重组为仪表盘布局（替换 v4）

用户随后给出一套「仪表盘布局」样式规范（深色侧栏 + 顶部工具栏 + 四列 KPI + 大字号数字 + 绿增红减），要求整体替换 v4。三个规范内部的冲突点先确认再动手：

1. **整体替换还是叠加** → 整体替换（`app.css` 全删，不做两套并存）；
2. **深色侧栏用什么色** → 用品牌红 950（`#210706`）。stylekit 默认 `gray-900` 是冷灰，和整站暖灰中性色打架；
3. **是否引入 Tailwind** → 引入（3.4.17 + PostCSS），品牌色阶写成 `tailwind.config.js` 里的 token，而不是散落十六进制。

实现上被明确约束的几件事：

- **先补数据层，再做界面。** 新增 `src/lib/metrics.ts`，KPI 与图表的所有数字都从真实 `HistoryOrder` 派生：环比是近 30 天 vs 前 30 天真实对比，上一窗口没有样本就输出「近 30 天没有新单」「样本不足，未做环比」，不编造。
- **图表手写 SVG，不引图表库。** 消费趋势用面积折线 + 单调三次插值（`t = 0.16`，避免普通样条过冲出现假低谷）；下单时段用环形图 + 图例。
- **六个页面要真的能走通：** 概览 / 开始点单 / 常用方案 / 订单记录 / 门店 / 关于，不是六个空壳。

**这一阶段真实修掉的 bug（都是"看着对、量出来错"的类型）：**

1. 折线图纵轴显示 `¥2.5k` / `¥50`：`t.v` 是「分」，被直接当「元」显示；`niceMax` 又取 10 的幂，28 元账单画在 50 元轴上浪费一半高度 → 新增 `axisLabel(cents)` 先除 100，`axisOf()` 按「整数步长 × 4」选刻度；
2. 纵轴顶端 `¥32` 但峰值只有 `¥28`：网格值取了 `step` 而非 `max / 4` → 改成 `const gridValue = max / 4`；
3. 折线图只占卡片左半、字号缩成 8px：`viewBox 720×320` 压到 520px 容器，12px 字被等比缩掉 → 改 `W = 560 / H = 250`；同时 `flex flex-1 items-center` 的子项在 row 方向会收缩到内容宽度 → 补 `w-full`；
4. 环形图两段数据拿到两个几乎一样的深红：配色按分桶索引分配，而不是按「实际有数据的分段数」→ 改为先数非零段，再分配；
5. 移动端 KPI 卡过高、点单页空状态卡只占上半屏 → `p-4` 降为 `p-3.5 md:p-5`，空状态容器补 `flex-1`；
6. 订单表门店列被截成「麦当劳上海浦东第二工业大…」→ 列宽 `max-w-[150px]` 放宽到 `[190px]`；
7. 截图里吸底栏在整页截图中压住侧栏 → 截图脚本显式给吸底栏补 `margin-left: 256px`（宽屏时）；
8. 真实流程点击后 502：`{"code":"MCP_TOOL","message":"门店可能已关闭或不在营业时间"}` —— 默认门店 1450543 在 22:15 已打烊，**不是界面缺陷**。换用营业到 23:59 的「悦荟广场餐厅」（`1450104`）后跑通；
9. 收尾自查时把说明文字的灰阶实际算了一遍：`#8a877f` 在白底只有 **3.59:1**，低于 WCAG AA 的 4.5:1。整条灰阶整体下移一档（`#111827` / `#57534c` / `#6f6a62` / 占位 `#7a756c`），侧栏的 `white/30`–`white/40` 提到 `white/55`–`white/60`，并逐对复核 Badge / Alert / 按钮 / 涨跌色，全部 ≥4.5:1。页面比之前略重一点，但 10px 的小字真的读得清了；
10. 同一轮还揪出三处「白卡套白卡」：方案条目、候选选项、"你刚才说"回声块原来都是白色卡片，直接嵌在白色面板里。改成 `#faf9f7` 浅底块 + 发丝线分隔，选中态用品牌色描边表示。全站从"卡片叠卡片"收敛为"只有一层卡片"，其余分组一律浅底。

**验收结果：**

- stylekit 的禁止项逐条规避：无 `rounded-none/3xl/full`、无 `shadow-2xl`、无 `font-black/extrabold`、无 `text-5xl` 以上、无单侧 accent stripe、无嵌套卡片、无渐变、无 bounce 缓动；
- 加载态与空状态 7 种场景逐个写，其中包括「核价中只给真实旋转指示和不确定进度条，不伪造分步打勾」；
- 320 / 360 / 375 / 390 / 414 / 430 / 768 / 1024 / 1280 / 1440 十个宽度**零横向溢出**；
- 用真实 MCP 在门店 `1450104`（悦荟广场，营业到 23:59）跑通 `随手配1+1`：自动匹配「人气经典随心配」，官方核价 **¥13.90**，`traceId 3d9b014`，预算 ≤¥16 判定在预算内；
- **全程未提交任何真实订单**，只到「已勾选、按钮已激活」为止。

### 阶段 6：概览页重组为编辑式工作台（替换仪表盘骨架）

仪表盘落地后，问题变成了另一种：**结构上是对的，观感上还是「后台管理系统」**。诊断下来是四件事叠加——

1. 四张 KPI 卡等宽等高，可四个指标的权重完全不同；
2. 每行都是 2:1，图表区、方案区、表格区三行结构复读；
3. 八块内容各占一张白卡，卡与卡之间只有 12px，卡片的边界不携带信息却把注意力切成八份；
4. 交互几乎全静态：KPI 不可点、单品榜不可点、时段图点了没反应、订单只能跳页看。

更根本的问题是信息顺序反了：这个页面八成的访问目的是「现在就点一单」，但首屏主体是四张统计卡加一张历史趋势图，核心动作被挤到右上角一个按钮。

改法是**换编排，不是换皮**：

- **主舞台 8 列 + 注解栏 4 列**（`xl:grid-cols-12`）。主舞台是一句话输入框 + 四条真实快捷短语 + 「最近一单 / 照这份再来」；注解栏是「我记住的」——最常点（带占比条）、套餐里最常选、客单价与累计、可点的下单时段。
- **两条通栏条带**：消费趋势与最近订单。不包卡片，只用 1px 分隔线切节奏。通栏与分栏交替，页面才有段落感。
- **概览页只剩输入框一个白色浮层**。其余全部平铺在 `canvas` 上，靠字号级差、40px 分隔和发丝线分层。「白底 + 阴影」的含义被收窄成：「哪里是白的、有投影的，哪里就是你要动手的地方」。
- **删掉 `KpiCard` 与 `HourDonut` 两个组件**（累计 163 行）。KPI 改成注解栏里的三个层级不同的数字，环形图改成可点的条形——环形图在 349px 宽的栏里占地太大，而且不可点。

**新增的四处交互都是真功能，没有一处只是动画：**

| 操作 | 行为 |
| --- | --- |
| 点注解栏的时段 | 订单列表筛到该时段，标题旁出现可清除的筛选标记（含命中单量），并滚动到列表 |
| 点趋势线上的数据点 | 展开对应订单明细并滚动到位；若它排在默认 6 行之外，列表自动放宽到能包含它 |
| 点任意订单行 | 就地展开明细（餐品、套餐子项、订单号、状态、实付、门店 + 再来一单），不跳页 |
| 点「按这个点一单」 | 把「再来一份 XX」填进首屏输入框，可改后再发 |

**这一轮真实修掉的问题：**

1. 图表被压成左下角一小段：`ResizeObserver` 首次回调拿到尚未完成布局的 0 宽，元素之后不再变尺寸，于是永远停在兜底值 → 改成挂载时实测 + 补一帧复量 + 接 `window resize`，并把兜底值去掉（量不到就不画）；
2. 写死 `viewBox` 的老问题被彻底解决：现在 `viewBox` 跟着实测像素宽走，1 SVG 单位 = 1 CSS 像素，字号在任何断点都是字面值，不会再被缩放；
3. 订单列表的 X 轴首尾标签被裁掉半个字：末位标签居中于最右数据点，文字外溢到 SVG 边界 → 首尾分别改成 `text-anchor: start / end`；
4. 热区跑到画布外面：首尾数据点的命中矩形各越界半格 → 夹在绘图区内（`max(PAD.l - 4, x - half)` / `min(w - PAD.r + 4, x + half)`）；
5. 筛选后 chip 显示「6 单」但实际午餐有 8 单：把「渲染行数」当成了「命中数」→ 拆成 `orders / total / matchCount` 三个参数，并把「筛选时列全部命中」写成规则；
6. 注解栏在 640–1279px 被拉成一条长带（时段条形横跨 600px，读数要来回扫）→ 该区间收成 2 列网格；
7. 移动端快捷短语横向截断成半个 chip → 改成换行（`flex-wrap`），不截断；
8. 窄栏里 `lg:grid-cols-4` 会把「平均客单价 + 累计下单」两个数字挤爆（需要 168px，实得 160px）→ 去掉该档，只保留 2 列与宽屏堆叠。

**验收：**

- 79 个测试仍全绿；`tsc --noEmit` 无错误；CSS gzip 7.2 KB + JS gzip 99.5 KB；
- 320 / 360 / 375 / 390 / 414 / 430 / 640 / 768 / 900 / 1024 / 1280 / 1440 / 1680 十三个宽度**零横向溢出**（脚本逐宽度检查 `scrollWidth - clientWidth` 并定位越界元素）；
- 11 张截图全部重拍，浏览器控制台零报错；
- 真实 MCP 链路仍然通：门店切到南京东路后走完「一句话 → 核价 → 确认页」，**全程未提交真实订单**。

### 阶段 8：按外部设计参考重建整套视觉系统（替换编辑式工作台）

编辑式工作台的结构没问题，但**用户仍然不满意观感**。这一轮的判断是：问题不在编排，在**视觉语言本身**——暖白底 + 虚白面板 + 12.5px 小字，落在屏幕上就是"一堆浅色块"，缺少一个能让页面立刻安静下来、同时有刊物气质的底子。

用户直接给了一个本地参考项目（`C:\study\olay\fronted`，另一款小红书 AI 内容鉴别工具的产品），要求"按这个风格做"，并明确**不得修改参考目录任何文件**。处理方式：完整读取它的 `App.tsx`（6194 行）、`index.css`（2347 行）与构建产物截图，提炼出它的设计语言，再在Tailwind 里重建 token 与组件——参考目录全程只读，连静态预览都是用 `python -m http.server` 托管它自己的 `dist/`。

**提炼出来的四条规则：**

| 参考项目的做法 | 我们的落地 |
| --- | --- |
| 近白底 + 三团极淡光斑 + 72px 细网格，网格上下 mask 淡出 | `body::before`（fixed）铺 `#faf8f6` + 三团radial 光斑 + 网格，`mask-image` 上下淡出 |
| 衬线大标题（`Noto Serif SC`，`font-weight 500`，`letter-spacing -0.035em`，`line-height 1.08`） | `.display` 类；**所有大数字也用衬线**——无衬线大数字像报表，衬线数字像刊物 |
| 微缩 `DM Mono` 标签（9.5px，`letter-spacing .16em`）做编号与口径 | `.eyebrow` 类，只出现在栏目编号、数据口径、时间戳 |
| 只有两类容器：`.float`（白得实 + 投影 + 背景模糊）与 `.panel`（白得虚 + 发丝线） | 同样两类，**并写死"面板里不再套面板"**；`.panel` 白度不低于 0.72，再淡就和底色糊成一片

由此推翻并重写了：深色侧栏（改为半透明白 + 发丝线 + `backdrop-blur`）、顶栏的搜索/通知/账号三件套（改为栏目名 + 口径 + 胶囊搜索）、Hero（改为居中扉页）、统计条带（从右侧注解栏移到通栏，用发丝线切四格）、`Card`/`CardHead` 两个组件（并入 `Panel`/`SectionHead`），以及 `SpendTrend` / `PlansGrid` / `OrdersTable` / `AdjustResultView` / `ConfirmSheet` / `StorePicker` 的视觉重绘。

**这一轮真修掉的问题（都不是"好不好看"，是错的）：**

1. **候选标题自相矛盾**：菜单改名（随心配1+1 → 人气经典随心配）后，候选仍叫「原样不变」，界面上等于一边说"没改"一边换了商品 → 在 `/adjust` 里按 `matchPlan` 的 `status === 'renamed'` 把标签改成「照旧 · 按当前菜单对齐」；
2. **门店列表不标营业状态**：截图脚本在 23:53 选到一家刚打烊的店，核价直接失败「门店暂停营业」→ 列表每行补「营业中 / 至 23:59」或「休息中 / 06:30 起」，不再让用户靠失败反推；
3. **小字号灰阶不达标**：口径标签用的 `#8d837a` 只有 3.50:1（AA 要 4.5:1）→ 整档提到 `#736a61`（5.00:1 on canvas / 5.30:1 on white），图表轴标签与空状态图标同步；
4. **浮层里套红框**：全局 `:focus-visible` 在 textarea 上画了一个方框，而外层 `.float` 已经在 `focus-within` 时整层换环 → 玻璃盒里又出现红盒子，改为浮层内输入框不描边、由外层承担焦点指示；
5. **中文按 `ch` 定宽被折成两字行**：`max-w-[56ch]` 在中文里只有 ~390px，一句说明被折成「…重新 / 核。」→ 全部改成 rem 定宽 + `text-pretty`（共 7 处）；
6. **标题的逗号缝隙**：全角逗号自带一个字宽空白，62px 下看起来像两个空格 → 逗号单独包一层 `mr-[-0.14em]`，实测字形间距从 59.6px 收到 50.8px；
7. **副标题断在词中间**：「…压到 20 元 / 以内——」被拆开 → 断行写死 + `text-pretty`；
8. **「用它」藏在 hover 里**：概览页方案清单的核心复用入口在触屏上根本发现不了 → 改为常驻，右侧留白随之收掉；
9. Hero 标题的 JSX 换行会在「老样子」前后插入行内空格 → 写成一行。
